# 小说本地化工作台

这是一个只在 Windows 本机运行的桌面程序，不再使用浏览器界面。

## 启动

双击：

```text
启动小说本地化工作台.bat
```

首次启动会在项目内创建 `.venv` 并安装 PySide6 桌面组件；以后启动会直接打开
独立窗口。关闭窗口即可退出程序。

## 当前功能

### 01 项目导入

- 新建小说项目，或把后续 TXT 章节加入已有项目。
- 支持一次导入多个拆分章节。
- 章节按内容校验，重复内容不会再次导入。
- 可附加本项目专用的 Markdown、TXT、JSON 或 YAML 规则 / Skill。
- 已有项目无需再次导入 TXT，也可以单独追加 Skill；已有 Skill 支持单个编辑和多选删除。
- 更换 Skill 后，可在“翻译处理”页重新选择已导入章节生成新译文，旧译文版本仍会保留。
- 可设置人名、地名、人物称呼、医院名、食物名等任意替换类别。

### 02 API 与 Key

- 支持保存多套 API 和模型配置。
- 支持 OpenAI Responses API、Anthropic Messages API、
  Google Gemini Interactions API 和 OpenAI 兼容接口。
- API Key 使用 Windows DPAPI 绑定当前 Windows 用户加密保存。
- 可以在界面中实际测试连接；测试可能产生少量 API 费用。

### 03 翻译处理

- 选择项目、API 配置和一个或多个章节开始翻译。
- 章节队列支持勾选后批量删除；删除前会二次确认，并清理对应原文、译文和处理记录。
- 高亮任意章节后可打开“查看替换清单”，按类别查看该章使用的人名、地名及其他替换。
- 章节/预览区与日志区之间可拖动调节高度，翻译页右侧提供整体纵向滚动。
- 执行前明确选择“中文小说 → 日语本地化”或“日语原文 → 改名润色”。
- 点击“开始处理”即可；不再单独扫描整章或要求人工确认设定。
- 模型在处理正文的同一次请求中自动识别人名、地名等并生成新名称，避免重复发送整章正文，节省 Token。
- 每章翻译时自动附加：
  - 项目规则 / Skill；
  - 所有已确认的人名、地名、人物关系和项目长期记忆；
  - 上一分段的原文、译文及章节衔接信息；
  - 用户为本批次填写的额外要求。
- 模型必须返回完整译文和本章新出现的替换项。
- 每完成一章立即写回替换清单，下一章会直接使用最新记录。
- 同一章的前段产生的新名称会作为临时记忆传给后续分段；整章成功后才正式写入项目清单。
- 同一原词已有目标词时，不允许模型自动生成第二个名字。
- 人名、地名等强制改名类别不允许保存“原词和新名称相同”的映射；历史同名错误映射会被忽略并要求重新确认。
- 原文中不存在的替换项不会写入。
- 完成后会检查原人名、地名等强制改名原词是否残留；可逐项标记误报、手动指定类别和新名称，或选择额外付费的 API 重做。人名手动映射提供未使用的本地名字库候选。
- 每次翻译都单独保存译文版本和处理记录。
- 章节失败不会阻止后续章节继续处理，可以取消批次。

## 数据位置

```text
data/
├─ config/
│  └─ api_profiles.json          # API 配置；Key 为 Windows 加密内容
└─ projects/<项目编号>/
   ├─ project.json               # 项目、章节和翻译记录
   ├─ source/                    # 原文 TXT
   ├─ skills/                    # 项目规则 / Skill
   ├─ replacements/              # 分类替换清单
   ├─ memory/project_memory.json # 已确认人物设定、关系和章节衔接记忆
   └─ output/                    # 译文及每次翻译的元数据
```

`data` 不会加入 Git。请像备份小说原稿一样定期备份这个文件夹。

## 隐私和费用

项目资料平时只保存在本机。只有用户在“测试连接”或“开始翻译”的确认框中选择继续后，
程序才会把相应测试消息或所选章节、项目规则和替换清单发送给指定 API 服务商。
外部 API 可能收费，具体费用和数据处理方式以服务商规则为准。
